### Gap 3 Fixed — VmLifecycleManager wired into Provisioning Service

**File changed:** `services/provisioning-service/src/index.ts`

Conditionally instantiates `VmLifecycleManager(new DefaultAzureArmAdapter())` when
`AZURE_SUBSCRIPTION_ID` env var is set at startup. When the env var is absent (local
dev / CI), logs a warning and the executor falls back to no-op cleanup.

**Full terminate path (end-to-end):**
```
POST /v1/agents/:botId/terminate
  → ProvisioningJob { status: 'cleanup_pending', triggerSource: 'termination' }
  → ProvisioningQueueConsumer polls job
  → ProvisioningJobProcessor.processCleanupPendingJob()
  → DefaultProvisioningStepExecutor.cleanupResources()
  → VmLifecycleManager.terminateAgentVM(botId, tenantId)   ← ARM resource deletion
```
