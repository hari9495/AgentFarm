## Sprint 10 Features Shipped

### Track A — Full Desktop VM Contracts (`desktop-agent-contracts.ts`)

- `DesktopActionType` — discriminated union: `'click' | 'type' | 'key' | 'scroll' | 'open_app' | 'wait' | 'done'`
- `DesktopAction` — `{ action, target?, value? }` payload for each LLM vision-loop step
- `VisionLoopRequest` — `{ contractVersion, goal, maxIterations?, llmProvider? }` inbound request
- `VisionLoopResult` — `{ contractVersion, taskId, sessionId, goal, status, result, stepsTaken, finalScreenshot?, startedAt, durationMs? }` outbound result
- `CONTRACT_VERSIONS.DESKTOP_AGENT: '1.0.0'` registered in shared-types index
- Full desktop VM infrastructure (Flask vision-loop service, Dockerfile, api-gateway routes, dashboard panel) existed from prior work; these contracts are the shared-types anchor.

### Track B — VM Lifecycle Management (`vm-lifecycle-manager.ts`)

- `VMConfig` — `{ subscriptionId, resourceGroup, region, vmSize, imageUrn, agentImage, tags: { botId, tenantId, workspaceId, purpose: 'agentfarm-runtime' } }`
- `VMProvisionResult` — `{ contractVersion, vmId, resourceGroupName, vmName, privateIp, containerEndpoint, managedIdentityId, region, provisionedAt }`
- `VMDeletedResource` — union of all Azure resource types cleaned on teardown
- `VMTerminateResult` — `{ contractVersion, botId, tenantId, success, resourcesDeleted, terminatedAt, errorMessage? }`
- `CONTRACT_VERSIONS.VM_LIFECYCLE: '1.0.0'` registered in shared-types index
- `AzureArmAdapter` interface — injectable; `DefaultAzureArmAdapter` implements via `fetch` + Azure ARM REST API
- `VmLifecycleManager` — `provisionAgentVM(config)` + `terminateAgentVM(botId, tenantId)` with full ARM orchestration (resource group → VNet → NSG → NIC → VM → container deployment)
- `default-step-executor.ts` wired to `VmLifecycleManager` for real provisioning path
- `queue-consumer.ts` fixed: polls BOTH `queued` AND `cleanup_pending` jobs in parallel (previously only `queued`)
